# 二期排期（v5.0 起）

> **本文件的性质**：首版（v1.0–v4.0）交付完成后，本仓库第一次把"二期"排出来。
> **取证规矩**：每一条都给出处；任务卡与 PRD 的句子逐字引用并核对过行号；没有出处的判断一律标成「本文件的取舍」，不冒充规格。
> **本文件不是开工授权**：卡片 165 行红线仍然生效——「📌 二期内容（真实微信支付对接/多院区/医生课酬/消息推送/企微公众号等）**首版一律不做**，清单见附录 A。AI 不得顺手实现。」

## 0. 排期之前先立三条事实

1. **PRD 没有二期排期表。** PRD §十「项目里程碑建议」（638–651 行）十个阶段全部是首版内容，合计「**约20周**」，
   到第九阶段「联调测试、性能优化、安全审计」为止。所以下面第 3 节这张表是本仓库第一次排二期，
   顺序依据只有卡片 791 行那一句「**二期建议顺序**：真实支付 → 多院区 → 消息推送 → 对账 → 票据」加上依赖关系本身。
2. **卡片给的顺序不是偏好，是依赖。** 附录 A 那一列「出处」里已经埋了两条硬约束：
   788 行对账「依赖退款变更流水，**必须最后做**」、789 行票据「定稿留版，**独立一期**」。
3. **附录 A 有两条在本仓库找不到需求原文**（第 4 节逐字举证）。照抄进排期会凭空多出两块工作量。

## 4. 附录 A 里有两项在本仓库找不到需求原文

这两条不是"要不要做"的问题，是**它可能根本不属于这个项目**，先举证再决定：

| 附录 A 项 | 卡片标称出处 | 实际查证 |
|---|---|---|
| 医生课酬计算（785 行） | PRD 九章 | PRD §九（600–637 行）标题是「**接口需求（概要）**」，全表是各模块的端点清单；**全文 grep「课酬」0 命中**，也没有任何课酬/薪酬相关的表或实体 |
| 教材库存管理（787 行） | PRD 九章 | 全文 grep「教材」**0 命中**；库里的表也没有任何教材/库存实体（见下方判断段的数据面印证） |

**本文件的判断（标注为判断，不当规格用）**：这两行极可能是这套任务卡**改编时没删净的残留**——
本仓库的任务卡流程是从一个教育培训项目的卡流程改来的（这一条来自项目立项时的口述历史，**卡片文档里没有任何一行这样写过**，
我按词根 grep 过「教育/培训/改编/参考」，卡片全文只命中第 305 行的「URL 模板」，与出处无关）。
另外从数据面也印证：当前库里 **35 张表**（含 `flyway_schema_history`）按 `book`/`stock`/`salar` 之类词根扫下来，
只命中 `payment_record` 一张，没有任何教材或库存实体。
处置建议：**不排工时**，改为向 PRD/流程作者确认是否删除；
若确认要保留，得先补需求原文——卡片 824 行（附录 C）早就给了规矩：
「需求有歧义 → 停，去 PRD 找原文；**PRD 也没写的（如退费算法），记进附录 A，不让 AI 自由发挥**。」
